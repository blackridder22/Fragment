## Migration and packaged host

`output/v0.0.8/migration-copy-report.json`: synthetic schema-4 Vault upgraded to 5;
3 Frames, 144 memberships and 144 assets; every recorded ID and original SHA-256
preserved; no foreign-key violations. Separate tests inject migration failure
and verify rollback. This was not the user's Vault. A .7 binary cannot open

`output/v0.0.8/packaged-host-smoke.json` verifies the actual bundled host:

- SVG/PNG HTTP capture, exact original hashes, source/page URLs, SQLite rows,
  palettes and PNG derivatives.
- A 9.105-second SVG response succeeds; the queued ping has the correct ID.
- A response exceeding the total download budget fails at 20.002 seconds.
- Killing a real SVG child leaves the host connected; its next capture succeeds.
- Host close/reopen retains data and reuses the saved asset on duplicate capture.
- External SVG resources fail explicitly.

This exercises the native executable, HTTP and SQLite. It does not exercise the
Chrome toolbar, injection, Frame picker or desktop focus behavior.

## Native UI evidence and remaining gates

`output/v0.0.8/native-user-imports.json` verifies six user-imported fixtures in
the packaged QA app, including two SVGs: every original matches the checked-in
source hash, derivatives are PNGs and palettes are ready. The refreshed final QA
app reopened the same Vault and all six originals and palettes remained intact.
Its startup snapshot reported the same 78 active memberships. The import notice also
showed three failures whose files/reasons were not exposed by the old notice.
The implementation now adds per-file error details, Retry and Dismiss; that new
disclosure still needs native interaction verification.

Observed in the isolated native app: swatch copy feedback, Find this color
updating the gallery, invalid-HEX feedback, Escape dismissal and Clear.
Screenshots: `output/v0.0.8/palette-copy-native.jpg` and
`output/v0.0.8/color-invalid-native.jpg`. The user completed a native import and
reported appropriate colors. Native AX inspection showed the selected two-color
PNG with blue 75% / green 25%. Clipboard feedback alone does not prove the OS
clipboard contents or SVG Copy Image. In the instrumented native app, an SVG
preview switched from Fit to 400%, finished its 4096-tier PNG request and showed
the maximum-resolution message. The Dark background selection also persisted.
These AX/control/cache checks do not establish visual sharpness or panning.

macOS automation intermittently returned stale/blank windows,
`noWindowsAvailable`, missing AX trees and ScreenCaptureKit error -3811. The user
confirmed the library was visible. Instrumentation later recorded an existing
Tauri ACL denial for title-bar `start_dragging`; the specific
`core:window:allow-start-dragging` permission was added. The blank automation
capture is not classified as a confirmed SVG rendering defect; clean
foreground/relaunch verification remains required.

Release gates still to execute:

1. SVG picker import is verified above; Finder drag/drop remains pending. Check Fit/100/200/400% sharpness, pan,
   three backgrounds, warning/error/retry/repair states and rapid navigation.
2. SVG Copy Image pasted into another native app as PNG; Reveal Original and
   original SVG verification. Complete light/dark, minimum-window, keyboard/focus,
   indexing-progress and filtered-revision refresh states.
3. Three 30-second native scrolling runs at 1,000 assets against .7, including

4. Open 100 distinct SVG previews twice; measure attributable app/WebView retained

5. Real Chrome toolbar → selected HTTP(S) SVG → Frame picker → native host →
