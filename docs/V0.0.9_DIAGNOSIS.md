# Fragment v0.0.9 — Performance and UX diagnosis

Date: 2026-10-04. Source: `vbeta0.0.8` after the v0.0.8 feature work. This document is the
shared brief for the v0.0.9 worktrees in `docs/worktrees/`. It records what was measured, what
is slow or confusing, and why, so every worktree starts from the same facts.

## Verdict

Tauri is not the problem. The author's own Vault holds 169 Fragments in a 576 KB SQLite file,
and the v0.0.8 QA harness shows the Rust side returning a page plus count in 13.7 ms p95 at
10,000 rows. The slowness and friction come from above the backend:

1. Every derivative image is a lossless PNG, so one gallery page moves ~16 MB and one preview
   decodes a multi-megabyte image.
2. `apps/desktop/src/App.tsx` is a 3,939-line component with zero memoization that re-renders
   every card on every state change and fetches the same data two to five times per interaction.
3. The v7 UI uses Frame and Fragment backwards and silently drops 57 feedback messages.
4. 2,904 lines of dead TypeScript and ~3,370 lines of dead CSS still ship and collide with live styles.

## Baseline measurements

| What | Measured |
| --- | --- |
| Vault | 169 active Fragments, 576 KB SQLite, 92 MB originals |
| Thumbnails (640 px PNG) | median 273 KB, p90 439 KB, 44 MB total |
| Previews (1600 px PNG) | median 1.3 MB, p90 2.3 MB, 220 MB total, 2.4x the originals |
| 12 thumbnails re-encoded | PNG 2.99 MB -> JPEG q85 0.97 MB (3.1x) -> WebP q82 0.37 MB (8.2x, alpha kept) |
| One 1600x702 preview | PNG 1.39 MB -> JPEG q88 415 KB -> WebP q85 175 KB |
| Frontend bundle (`vite build`) | JS 427 KB (125 KB gz), CSS 164 KB (27 KB gz), 9,627 CSS lines |
| Dead TypeScript | 19 files, 2,904 lines unreachable from `main.tsx` |
| Dead CSS | 368 of 562 rules in `globals.css` (~3,370 of 4,622 lines) reference classes no live component uses |
| App.tsx | 21 useState, 30 useEffect, 23 useMemo, 18 useRef, 0 React.memo, 21 `refreshSnapshot` call sites, 7 `window.confirm`, 57 `setStatus` calls that are never rendered |
| Backend (QA, 10k rows) | unfiltered page + count 13.7 ms p95; color page + count 34.2 ms p95 |
| Native scroll frame time, retained memory | never measured (`docs/V0.0.8_QA.md` gates 3 and 4 are still open) |

Dead-code and dead-CSS numbers come from a reachability walk starting at `apps/desktop/src/main.tsx`
over static imports, then matching every class selector in `src/styles/*.css` against the reachable
`.tsx` sources. Thumbnail numbers come from `~/Library/Application Support/Fragment/` on the author's
machine; re-encodes used `sips` (JPEG) and `cwebp` (WebP) on copies.

## Findings, ranked by impact

### 1. PNG derivatives (highest impact, low risk)

- Location: `crates/fragment-core/src/thumbnails.rs` (`generate_thumbnail`, `generate_preview`),
  `crates/fragment-core/src/previews.rs` for SVG tiers.
- Category: too much.
- Evidence: table above. A 60-item page is ~16 MB of thumbnail bytes through the asset protocol
  handler plus WebKit decode. The overlay loads a 1.3 to 3.8 MB PNG per Fragment with no prefetch.
  Previews are larger than most originals, so the Vault on disk is 3.9x the size of the images in it.
- Fix: lossy WebP with alpha (libwebp via the `webp` crate; the `image` crate only writes lossless
  WebP) or JPEG for opaque sources with PNG reserved for alpha. Skip the preview when the original
  is already <= 1600 px and browser-displayable. Background regeneration for existing Vaults.
  Update AGENTS.md section 8, which currently mandates PNG.
- Expected: 3 to 8x fewer bytes per page, faster scroll and preview open, 150+ MB disk reclaimed.
- Verify: derivative sizes p50/p90, import time on `fixtures/media/nasa-blue-marble.jpg`,
  scroll recording at 1,000 items (`scripts/qa/README.md`).

### 2. App.tsx god component and render churn

- Location: `apps/desktop/src/App.tsx`; `assetSourcesFor` (line ~1999) and inline `folderNameFor`
  props are new closures each render; render-time side effect at line ~2335
  (`importPathsRef.current = importPaths`); client re-sort with `Date.parse` in the comparator at
  line ~1143; 0 `React.memo` in the tree.
- Category: render churn.
- Evidence: any state change (status string, drag hover, palette event, undo-toast timer) re-renders
  the whole gallery because every card receives fresh function props.
- Fix: library store with selectors, page-local state in page components, precomputed asset URLs
  per page item, memoized card with primitive props. Then consider the React Compiler.
- Verify: React Profiler commit counts while hovering and dragging; perf flag frame intervals.

### 3. Duplicated and redundant fetches

- Location: `App.tsx` debounced effect (line ~902) re-runs on `activeView`; `changeView`
  (line ~2367) also calls the loader directly; snapshot and that effect both fetch page one at
  launch; tags fetched twice for the same Fragment (lines ~1483 and ~1519); `refreshSnapshot`
  (21 sites) reloads snapshot + Smart Frames + tags + page after rename/move/link/restore;
  `filteredFragments` re-filters the server-filtered page.
- Category: too often, too serial.
- Evidence: two identical page queries on every view click; the 180 ms debounce delays clicks on
  filter pills, sort and view; typing changes the grid twice per keystroke.
- Fix: one query-key-driven loader (dedupe in flight, cancel stale), text-only debounce, optimistic
  patches instead of full snapshot reloads, no client re-filtering.
- Verify: `invoke` count per interaction via the perf flag; target is 1.

### 4. Inverted vocabulary in the v7 UI

- Location: `apps/desktop/src/v7/DesktopShell.tsx` (Add menu: "New Fragment / Create a folder for
  Frames", "Import Frames / Add images from this Mac"; tree header "Fragments"), `VaultPage.tsx`
  ("{n} Frames" for images, "Frames from across your Vault"), `FocusedFrameOverlay.tsx` (destination
  select labelled "Fragment"), `App.tsx` ("Smart Fragment", "Renamed Fragment", "Inbox is a protected
  Fragment", "No Frames in your Vault yet").
- Evidence: introduced in commit `a5d67ec` (v0.0.7). The extension says "Save Fragment" into a
  "Frame", the landing page says "organize them into Frames", and the database and AGENTS.md agree.
- Decision for v0.0.9: AGENTS.md is correct. Frame = collection, Fragment = saved image.
- Fix: string pass plus a test that fails on the inverted phrases.

### 5. Silent feedback and dialog defects

- `setStatus` is called 57 times but `status` is never rendered. "Image copied", "Restored Frame",
  "Frame tags saved" and the import summaries are invisible.
- Add and Sort menus in `DesktopShell.tsx` never close on outside click (no document listener).
- Seven destructive flows use the native blocking `window.confirm`.
- `VaultPage.tsx` shows only `frames.slice(0, 4)` folder cards with no indication that more exist.
- The Forward button in the window bar is permanently disabled (`onForward` is never passed).

### 6. Masonry crops every image

- Location: `apps/desktop/src/v7/FrameGallery.tsx` lines ~95 to 147 (`PAPER_MASONRY_HEIGHTS`,
  `masonryColumns`), `styles/v7-gallery.css` (`object-fit: cover`).
- Evidence: heights come from a fixed pattern by column index, not from the stored width/height.
  Columns are filled by index modulo, not shortest-column. No virtualization: after ten pages,
  600 image nodes stay mounted.
- Fix: real aspect-ratio masonry, shortest-column placement, windowing on the `.v7-frames-page`
  scroll container.

### 7. Dead code and dead CSS

- 19 unreachable files are the pre-v7 UI: `features/frames/FrameNavigator.tsx`,
  `features/fragments/FragmentInspector.tsx`, `features/filters/FilterPanel.tsx`,
  `features/fragments/FragmentDetailSheet.tsx`, `features/settings/SettingsPage.tsx`,
  `components/FragmentCard.tsx`, `components/FrameCard.tsx`, `components/IconRail.tsx`,
  `features/fragments/FragmentQuickPreview.tsx`, `features/selection/SelectionToolbar.tsx`,
  `components/LoadMoreSentinel.tsx`, `features/fragments/fragment-metadata.ts`,
  `features/frames/FrameBreadcrumbs.tsx`, `components/MasonryGrid.tsx`, `components/FrameChipBar.tsx`,
  `features/trash/TrashedFramesList.tsx`, `app/AppShell.tsx`, `lib/format.ts`, `components/EmptyState.tsx`.
- Two thirds of `globals.css` styles those files. The live card reuses the old `fragment-card`
  class, so both generations of rules cascade onto it, which is where the `!important` overrides come from.

### 8. Motion has no system

- 8 keyframes, almost all spinners. Transitions are 120 to 160 ms `ease` or `linear` (68 uses of
  `linear`). No duration or easing tokens. The overlay mounts with no enter/exit while applying an
  8 px `backdrop-filter` over the whole gallery. Reduced motion is a global `1ms !important` override.
- Direction: tokens first, then purposeful motion per page on transform and opacity only.

### 9. Backend items, lower priority at this scale

- One `Mutex<Connection>` (`crates/fragment-core/src/db.rs`) serializes every query, including a
  palette loop that wakes every 500 ms for the app's lifetime even when idle
  (`apps/desktop/src-tauri/src/media_commands.rs`).
- macOS window-chrome refresh forces a synchronous redraw on every `Resized` tick
  (`apps/desktop/src-tauri/src/lib.rs`, `window_chrome.rs`).
- A blocking `reqwest` client with its own runtime thread is built at startup though the desktop never downloads.
- No `[profile.release]` (LTO, codegen-units, strip) in the workspace `Cargo.toml`.
- Search is an unindexed `instr(lower(...))` scan over eight columns; FTS5 belongs on the roadmap before 10,000 items.

## Measurement protocol for every worktree

Record before and after under the same conditions and put the numbers in the PR body with the command used.

- Bytes: `pnpm --filter @fragment/desktop exec vite build` prints JS and CSS sizes.
- Interaction cost: the dev perf flag (`localStorage.setItem("fragment:perf", "1")`, built by
  worktree 00) logs `invoke` counts, rAF frame intervals (p50/p95/max, stalls > 100 ms),
  launch -> first thumbnail, and preview open -> image decoded.
- Scale: build a 1,000-item QA Vault with `media_qa_corpus` + `seed_media_qa`
  (`scripts/qa/README.md`) and run with `FRAGMENT_APP_DATA_DIR` set to it. Never use the real Vault.
- Render churn: React DevTools Profiler, "Highlight updates", hover a card and open a toast.
- Memory: Activity Monitor on the `Fragment` and its WebContent process after 100 preview opens.

Improvement = ((before - after) / before) x 100 for lower-is-better metrics.
