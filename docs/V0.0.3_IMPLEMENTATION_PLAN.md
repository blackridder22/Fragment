# Fragment v0.0.3 Implementation Plan

Status: Approved and in implementation  
Baseline branch: `v0.0.2`  
Baseline commit: `0d1d73e` (`chore: establish Fragment v1 baseline`)  
Implementation branch: `v0.0.3`

## 1. Release intent

Fragment v0.0.3 is a reliability, performance, and UIX release. It will preserve the clean image-first visual direction of v1 while removing the bugs and stalls that make the app feel less native than it looks.

The release has four priorities, in this order:

1. Protect user data and make shared Fragment behavior correct.
2. Make launch, browsing, selection, import, and capture measurably faster.
3. Max out the UIX without replacing the current design language.
4. Make the desktop app, native host, and extension one reproducible release.

The plan deliberately keeps SQLite. Current evidence does not support replacing it: the live database is small and the complete active metadata query is fast. The larger costs are repeated full refreshes, asset delivery failures, image decoding, base64 fallback IPC, oversized derived media, and mounting every gallery item in React.

### Foundation delivery status

The release/test foundation slice establishes:

- A real zero-warning ESLint flat configuration using the dependencies already locked at the root.
- Deterministic synthetic Vault fixtures for 60, 1,000, and 10,000 Fragment memberships without reading a user Vault or database.
- An in-memory metadata benchmark for parse, first-page, membership-index, and Select All costs.
- A macOS clean-checkout CI workflow for lint, typecheck, tests, Rust format/Clippy/tests, extension build, and desktop frontend build.
- Current capture, native messaging, shared-asset, Trash, roadmap, and version documentation.
- A v0.0.3 changelog entry marked in progress.

This slice does not change application, core, database, or native-host behavior. Tracing, baseline timing capture, Clippy fixes, schema changes, and product implementation remain in their owning phases below.

## 2. Product principles for v0.0.3

- Keep the calm, neutral, image-first interface.
- Keep transparent PNGs transparent. Do not add a forced tile background or crop them.
- Preserve each image's real aspect ratio in the gallery.
- Keep common actions close, contextual, and keyboard accessible.
- Never freeze the UI while importing, hashing, generating previews, or contacting the native host.
- Store one asset once, then share it across any number of Frames through memberships.
- Make destructive behavior explicit, reversible, and transactionally safe.
- Measure performance before and after each optimization.
- Avoid a visual rewrite, a database rewrite, and new product categories in the same release.

## 4. Definition of success

### Reliability

- No operation can create two asset files for the same SHA-256.
- A given asset can have at most one membership in a given Frame.
- Multi-Frame capture is atomic or returns an explicit result for every requested Frame.
- Dragging a Frame to Trash never permanently deletes it.
- Delete Everywhere cannot leave database rows and files in contradictory states.
- Restore handles duplicate and deleted-Frame conflicts explicitly.
- Retention settings actually purge expired items.
- Select All always means the complete current filtered result, not only mounted cards.
- Navigation always closes or updates an obsolete detail sheet.

### Performance budgets

| --------------------------------- | --------------------------------------------- |
| Warm app shell visible            | 400 ms or less                                |
| Cold app shell visible            | 800 ms or less                                |
| First 30 thumbnails decoded, warm | 900 ms or less                                |
| First 30 thumbnails decoded, cold | 1.5 s or less                                 |
| Current-vault metadata snapshot   | 75 ms or less                                 |
| 10,000-Fragment metadata snapshot | 200 ms or less                                |

| 12 MP thumbnail ready             | 1.5 s p95 or less                             |

### UIX quality

- At the minimum 960 x 680 window, the first gallery image begins by y=240.
- The toolbar occupies at most two rows between 960 and 1179 px, and one row at 1180 px or wider.
- No permanent selection toolbar is shown when zero items are selected.
- Every pointer action has a keyboard or menu equivalent.
- Dialogs trap focus, close with Escape where safe, and restore focus to their trigger.
- Normal text meets 4.5:1 contrast and controls expose visible focus.
- Light, Dark, and System render correctly on first paint without a theme flash.
- Motion remains between 120 and 220 ms for routine transitions and is disabled or simplified with Reduce Motion.

## 5. Architecture decisions

### 5.1 Keep SQLite

SQLite remains the metadata store. v0.0.3 will improve schema versioning, indexes, transaction boundaries, and query shape before considering additional connections or a replacement database.

Read connections will be added only if lock-wait instrumentation proves the current mutex is a bottleneck. A server cache, Redis, or an additional database would add complexity without addressing the current asset and render costs.

### 5.2 Assets and memberships are different entities

The asset owns the original, thumbnail, preview, SHA-256, dimensions, MIME type, and file size. A Fragment membership connects that asset to one Frame and owns Frame-specific metadata such as title, note, and deletion state.

Required invariant:

```txt
assets.sha256                         UNIQUE
fragments(frame_id, asset_id)         UNIQUE
```

One image selected for Frames A and B creates one asset and two memberships. Removing the membership from A leaves B and the asset intact. Delete Everywhere soft-deletes every membership and moves the shared asset toward retention-based purge.

### 5.3 Paginated metadata with global selection

The UI must not load and mount the complete Vault to support Select All. Selection will use a query-aware model:

```ts
type SelectionState =
  | { mode: "explicit"; ids: Set<string> }
  | {
      mode: "all-matching";
      queryKey: string;
      excludedIds: Set<string>;
      total: number;
    };
```

Batch commands will accept either explicit IDs or a validated filter descriptor plus exclusions. This keeps Select All correct for thousands of results without materializing every card.

### 5.4 Background jobs, not frontend loops

Import, hashing, derived-image generation, capture, and purge work belongs in Rust background jobs. React owns queue presentation and user decisions, not file processing loops. Tauri channels will deliver typed progress events.

### 5.5 Derived files remain replaceable caches

Originals remain the source of truth. Thumbnails and previews remain PNG in v0.0.3 for transparent-image and WebKit reliability, but their dimensions, compression, generation time, and cache lifetime will be measured and bounded.

### 5.6 Application and protocol versions are separate

All package, Cargo, Tauri, host, and extension manifests share application version `0.0.3`. `extensionVersion` identifies the sending extension build, while `pong.version` identifies the host build. Neither is a negotiated protocol revision.

Explicit protocol negotiation remains Phase 8 work. When added, the previous client version must remain compatible, and protocol changes must update the shared TypeScript types, Rust models, native-host tests, and protocol documentation together.

## 6. Delivery phases

Each phase must leave the application buildable and testable. Product code is implemented on the `v0.0.3` branch.

### Phase 0: Freeze the baseline and add measurement

Goal: make every later performance and reliability claim reproducible.

Implementation:

- Create branch `v0.0.3` from the approved baseline.
- Decide whether the baseline receives an honest `v0.0.2` tag or a `v1.0.0` tag.
- Add one version command that updates npm packages, Cargo packages, Tauri config, and the canonical extension manifest.
- Pin supported Node, pnpm, and Rust toolchains.
- Add `tracing` spans for core startup, migrations, snapshot queries, serialization, asset failures, imports, capture, and purge.
- Add browser performance marks for React mount, first shell commit, first card commit, and first decoded thumbnail.
- Add generated benchmark Vaults at 60, 1,000, and 10,000 metadata records without copying or reading user data.
- Record a v1 baseline report for cold launch, warm launch, focus refresh, import, selection, and scroll.
- Fix the four existing Clippy warnings and make `-D warnings` a gate.
- Replace the fake lint scripts with real ESLint configuration.

Exit criteria:

- A repeatable command produces startup and interaction timings.
- Benchmarks do not include sensitive source URLs.
- TypeScript lint, Rust format, Clippy, unit tests, and builds are clean.
- No performance optimization is accepted without before/after evidence.

### Phase 1: Data safety and schema invariants

Goal: fix destructive and duplicate behavior before optimizing around it.

Implementation:

- Introduce a migration ledger using `PRAGMA user_version` or a dedicated migrations table.
- Add a pre-migration WAL checkpoint and versioned database backup.
- Add an additive `0002` migration for:
  - Unique Frame/asset membership.
  - Frame soft-delete and retention metadata.
  - Query indexes for active/trash ordering after query-plan measurement.
  - A Vault revision counter or metadata row.
- Rebuild legacy tables where needed so foreign keys and cascade behavior are consistent.
- Make multi-Frame membership creation transactional.
- Make Remove from Frame, Delete Everywhere, Restore, Empty Trash, and expiry purge transactional at the metadata level.
- Use a recoverable file-cleanup journal when database commit and filesystem deletion cannot be one transaction.
- Keep the system Inbox impossible to delete or move to Trash.
- Add explicit idempotency keys for extension capture requests.

Duplicate rules:

1. Same bytes, same Frame, active membership: do not create anything. Show the existing Fragment.
2. Same bytes, different Frame: offer Add Existing Fragment to This Frame or Never Mind. Add only a membership.
3. Same bytes found in Trash: offer Restore, Add to Another Frame, or Never Mind according to current memberships.
4. Same name and dimensions but different SHA-256: treat it as a different asset and offer a title rename only when the title conflicts.
5. Concurrent identical imports: the database constraint wins; the second request receives the same typed duplicate result as a normal duplicate.

Trash rules:

- A Fragment drag from a specific Frame moves only that membership to Trash by default.
- From Home or All, the user chooses Remove from This Frame or Delete Everywhere when more than one membership exists.
- Delete Everywhere soft-deletes all memberships and schedules the asset for purge.
- A Frame drag soft-deletes the Frame and preserves its memberships for restore.
- Restoring a Frame restores its membership visibility without duplicating assets.
- Purge deletes original and derived files only when no active or retained membership still references the asset.
- Default retention is proposed as 31 days, with 7, 14, 24, 31, and Never options.

Exit criteria:

- Failure-injection tests prove no destructive operation strands unrecoverable metadata.
- Legacy v0.0.2 database fixtures migrate without losing Frames, memberships, source metadata, or Trash state.
- Exact duplicates cannot create a second asset or a second membership in one Frame.
- Frame drag to Trash is reversible.
- Retention purge is restart-safe and idempotent.

### Phase 2: Fast startup and refresh

Goal: render useful content without loading the complete Vault and Trash.

Implementation:

- Add one async `load_library_snapshot` Tauri command returning:
  - Default Frame.
  - Frame summaries and counts.
  - Active total and trash total.
  - Current Vault revision.
  - The first 60 lightweight gallery records for the active query.
  - Asset root/configuration required by the frontend.
- Run all blocking SQLite work inside `spawn_blocking`.
- Do not list Trash records until Trash is opened.
- Replace full focus refresh with a cheap `vault_revision` check.
- Refresh only changed counts, pages, or memberships after mutations.
- Add cursor pagination for gallery metadata.
- Separate gallery summary models from full detail models.
- Remove redundant default-Frame and full-list calls from React startup.
- Ensure React Strict Mode development behavior cannot launch duplicate native jobs.

Exit criteria:

- Startup uses one primary snapshot round trip.
- An unchanged focus event performs no gallery reconstruction.
- Opening Trash is the first time Trash rows are loaded.
- Current and 10,000-record snapshot budgets pass.

### Phase 3: Reliable asset delivery and scalable gallery

Goal: eliminate broken previews, base64 storms, unnecessary decoding, and all-at-once rendering.

Implementation:

- Correct Tauri asset protocol scope and CSP for the Fragment app-data directories.
- If the standard asset protocol remains unreliable, add a root-scoped custom `fragment-asset://` protocol with path validation, MIME headers, cache headers, and traversal tests.
- Remove `asset_data_url` as the normal gallery fallback.
- Use thumbnail files in the gallery, preview files in details, and originals only on explicit demand.
- Version derived URLs so regenerated files invalidate WebKit caches.
- Regenerate a missing/corrupt derived file from the original in a background repair job.
- Reserve dimensions from metadata before an image loads to prevent layout shifts.
- Add `loading="lazy"`, `decoding="async"`, stable source arrays, memoized cards, and stable callbacks.
- Add incremental pages and `content-visibility` first.
- Introduce measured masonry virtualization only if the simpler approach misses the 1,000-item budget.
- Rework derived-cache policy:
  - Tune thumbnail and preview dimensions using visual QA.
  - Generate the thumbnail first.
  - Defer the preview until idle or detail open.
  - Bound preview cache growth and regenerate on demand.
  - Preserve PNG transparency.

Exit criteria:

- Valid asset paths produce zero base64 fallback IPC requests.
- The first page renders before the full result count is materialized.
- Scrolling 1,000 records meets the frame-rate budget without layout movement.
- Missing previews repair without requiring a relaunch.
- Derived storage is materially lower than the v1 baseline while transparent PNG QA passes.

### Phase 4: Native background import and duplicate UI

Goal: make imports immediate, cancellable, transparent, and non-blocking.

Implementation:

- Add a typed native import-job API with bounded concurrency of two files.
- Read, decode, dimension-check, and hash each file once.
- Reuse the prepared asset when creating one or many Frame memberships.
- Write originals and derived files through temporary paths and atomic rename.
- Emit per-item states through a Tauri channel:
  - queued
  - preparing
  - duplicate-needs-decision
  - writing-original
  - thumbnail-ready
  - complete
  - failed
  - cancelled
- Show an immediate local placeholder using the selected file while Rust prepares the managed copy.
- Replace `window.confirm` and `window.prompt` with a Fragment duplicate sheet.
- Support Skip, Add Existing to Frame, Rename Title, Restore, Retry, Cancel, and Apply to Remaining where valid.
- Keep the destination Frame fixed to the job unless the user explicitly changes it.
- Reconcile partial failures per item and never discard successful queue history because another file failed.
- Update only affected gallery records rather than issuing a full refresh.

Exit criteria:

- A 50-image import leaves browsing, search, and navigation responsive.
- Every item has a visible state, retry path, and cancellation behavior.
- No file is decoded or hashed twice.
- Duplicate resolution never creates an extra asset file.
- Completed images replace placeholders without card movement.

### Phase 5: Selection, navigation, and Trash interactions

Goal: make high-frequency organization workflows precise and fast.

Selection behavior:

- First selection activates a contextual command bar.
- `Command+A` selects the complete filtered query.
- `Command+click` toggles an item.
- `Shift+click` selects a contiguous range in visual order.
- `Escape` clears selection.
- Space toggles the focused item.
- Selection is pruned against the current active or Trash result set, never against an unrelated list.
- Filter changes either preserve a valid query-aware selection or clear it with an explicit rule.
- No lasso/drag rectangle is included unless a measured prototype proves reliable.

Navigation and detail behavior:

- Rail or Frame navigation closes stale detail, rename, and duplicate sheets.
- Fragment details support previous/next navigation in the current filtered order.
- Escape closes safely, focus is trapped, and focus returns to the source card.
- Add Copy Image with clipboard feedback.
- Add `Command+S` for details save and dirty-state protection on close/navigation.
- Broken originals show a recoverable error instead of a phantom card.

Trash drag behavior:

- Dragging over the Trash rail icon enlarges/highlights the target without moving layout.
- A successful drop animates a lightweight proxy toward Trash and keeps the current view open.
- An Undo toast restores exact memberships and Frame state.
- Keyboard and context-menu alternatives provide the same actions.
- Dropping a shared Fragment presents Remove from This Frame or Delete Everywhere.
- Dropping a Frame reports the number of affected memberships before confirmation.

Exit criteria:

- Select All reports the exact complete filtered count at 301, 1,000, and 10,000 records.
- No phantom or off-query IDs remain selected after refresh.
- Rapid Frame switching cannot leave duplicate Tauri drop listeners.
- Undo restores exact prior state.
- Detail navigation is complete with keyboard only.

### Phase 6: Max-out UIX pass

Goal: make the current design feel native, responsive, and intentional without making it visually busy.

Information architecture:

- Home contains the Fragment gallery and Frame filter chips.
- Frames is the sole management view for creating, renaming, arranging, and deleting Frames.
- Home does not mount the Frame management card grid below a long gallery.
- Trash is a real destination with Restore, Delete Forever, and Empty Trash.
- Settings contains only Appearance, Deletion, Extension Connection, and About.
- Do not expose an editable Vault path.

Compact shell:

- At 1180 px and wider, title, search, sort/filter, New Frame, and Import fit in one disciplined toolbar row.
- From 960 to 1179 px, the toolbar uses at most two rows.
- Sort and filter move into compact grouped controls or popovers when width is constrained.
- The selection toolbar appears only while selection exists.
- Frame chips have visible overflow affordances and do not push the gallery down.

Motion and feedback:

- Define shared durations and easing tokens for hover, press, sheet, toast, selection, import, and Trash motion.
- Animate transform and opacity for routine feedback; avoid layout-driven animation.
- Add restrained sheet transitions, card selection feedback, import completion, navigation crossfade, and Trash drop/undo.
- Respect `prefers-reduced-motion` for every animation, including shimmer.
- Use one toast/activity system for success, failure, undo, clipboard, import, and connector state.
- Keep status channels separate: extension health must never display an import or deletion message.

Theme and typography:

- Fix System theme before first React paint.
- Validate full Light, Dark, and System parity.
- Use the macOS system stack or locally bundled fonts; do not depend on blocked remote Google Font requests.
- Raise light-theme subtle-text contrast to an accessible value.
- Preserve the current business/calm hierarchy without decorative handwriting in operational controls.

Accessibility:

- Dialog focus trap and focus restoration.
- `aria-current` for rail destinations.
- `aria-pressed` for Frame chips and selection controls.
- Live regions for import, copy, save, restore, and connector status.
- Explicit labels and tooltips for icon-only controls.
- Minimum 44 x 44 px hit targets where practical.
- Full keyboard parity for drag-dependent actions.

Exit criteria:

- The minimum-window gallery starts by y=240.
- No clipped labels, overflow, or incoherent overlap at supported sizes.
- Light, Dark, System, increased contrast, and reduced motion pass manual QA.
- Core workflows are usable without a pointer.

### Phase 7: Frontend structure and maintainability

Goal: reduce regression risk while preserving behavior through small extractions.

The current `App.tsx` and global stylesheet are too large to safely carry the next release. Refactoring will follow feature boundaries, not a one-shot rewrite.

Proposed structure:

```txt
apps/desktop/src/
  app/
    AppShell.tsx
    routes.ts
    startup.ts
  features/
    library/
      LibraryView.tsx
      library-store.ts
      library-api.ts
    selection/

      SelectionToolbar.tsx
    import/
      import-store.ts
      ImportQueue.tsx
      DuplicateSheet.tsx
    details/
      FragmentDetails.tsx
    frames/
      FramesView.tsx
    trash/
      TrashView.tsx
      TrashDropTarget.tsx
    settings/
      SettingsView.tsx

    gallery/
    feedback/
    overlays/

    shell.css

    overlays.css
```

Rules:

- Extract only after behavior has a regression test.
- Keep server/native state separate from transient UI state.
- Keep card props stable and localize image-load state.
- Do not introduce a global state dependency unless React reducers and focused stores fail measured needs.
- Do not mix refactoring and visual redesign in the same commit.

Exit criteria:

- The root App coordinates routes and top-level providers rather than every workflow.
- Selection, import, Trash, and library refresh each have focused tests.
- Asset failure for one card does not rerender the complete gallery.
- CSS tokens and feature styles have clear ownership.

### Phase 8: Extension, native host, and production release

Goal: ship one coherent desktop-plus-extension system.

Extension and host:

- Make one extension manifest canonical and generate packaged copies from it.
- Keep the current logo and icons synchronized in popup, toolbar, and packaged ZIP.
- Use a persistent native connection with timeout, request-ID validation, retry/backoff, and reconnect state.
- Add protocol version negotiation with one-version backward compatibility.
- Make cancel stop or explicitly detach an in-flight capture, not only hide its UI.
- Make multi-image capture resumable per item and report partial results explicitly.
- Store/download one selected asset once, then add all requested Frame memberships in one transaction.
- Improve candidate rescans on infinite-scroll pages using scoped mutation work and intersection visibility rather than full repeated scans.
- Preserve user-directed capture. Do not add page-wide automatic bulk extraction.
- Add high-resolution candidate ranking and graceful fallback instead of failing the whole capture when one `originals` URL returns an error.

Packaging:

- Bundle `fragment-host` at a stable signed path inside `Fragment.app`.
- Install or repair the Native Messaging manifest from Settings only after the bundled host answers `ping`.
- Remove development localhost permissions from production extension output.
- Build desktop, host, and extension from one clean commit and one release command.
- Produce a deterministic extension ZIP, app bundle, DMG, checksums, release manifest, migration notes, and test report.
- Sign the app and nested host with hardened runtime.
- Notarize and staple the app/DMG when Developer ID credentials are available.
- Decide arm64-only, separate arm64/x86_64, or Universal 2 before the release candidate.

Exit criteria:

- Moving or cleaning the repository cannot break an installed production host.
- Host missing, stale manifest, ID mismatch, timeout, crash, and reconnect paths are tested.
- The packaged extension and app report compatible protocol versions.
- Release artifacts come from the same commit and include SHA-256 checksums.
- `codesign`, Gatekeeper, and notarization validation pass for the distribution candidate, or credentials are reported as the only external blocker.

Every release candidate must pass from a clean checkout:

```bash

cargo fmt --all -- --check

```

Installed-system smoke tests and distribution candidates additionally require:

```bash
pnpm smoke:native-host

spctl --assess --type execute --verbose=4 Fragment.app
```

CI will reject:

- A dirty worktree after version/build generation.
- A schema change without a numbered migration and upgrade fixture.
- A protocol change without aligned Rust and TypeScript tests.
- A generated manifest that differs from the canonical source.
- A performance regression beyond the approved budget.

## 9. Migration and rollback

- v0.0.3 migrations remain additive wherever possible.
- Before the first migration, checkpoint WAL and create a versioned database backup.
- Never modify or delete originals during migration.
- Derived assets may be versioned and rebuilt in the background.
- If migration fails, leave the original database and originals untouched and present a recoverable error.
- Rollback after a successful schema migration restores the matching app and database backup together. Reinstalling an older app against a newer schema is not considered safe.
- Keep the previous Native Messaging manifest until the new bundled host answers `ping`, then switch atomically.

## 10. Commit and review strategy

The implementation should use small reviewable commits in this order:

1. `chore: add v0.0.3 quality gates and performance baselines`
2. `feat(core): add versioned migrations and membership invariants`
3. `fix(core): make trash and shared deletion transactional`
4. `perf(core): add library snapshots and revision refresh`
5. `perf(desktop): make asset delivery and gallery incremental`
6. `feat(import): add native background import jobs`
7. `fix(desktop): replace selection with query-aware state`
8. `feat(desktop): complete details and trash interactions`
9. `refactor(desktop): split app workflows by feature`
10. `style(desktop): complete compact shell, themes, motion, and accessibility`
11. `fix(extension): harden capture lifecycle and native connection`
12. `chore(release): unify versions, packaging, signing, and artifacts`

No phase should combine a schema migration, broad React refactor, and visual redesign in one commit.

## 11. Approved implementation defaults

The implementation uses these approved defaults:

1. Baseline remains the honest code version `v0.0.2`.
2. Implementation branch is `v0.0.3`.
3. Trash retention default: 31 days.
4. Shared duplicate flow: always show the duplicate sheet before adding an existing asset to another Frame.
5. Frame Trash: soft-delete and restore complete Frames in v0.0.3 rather than blocking Frame drops.
6. Gallery strategy: ship incremental paging first; add a virtualization dependency only if measured budgets still fail.
7. Distribution architecture remains arm64-first for v0.0.3; Universal 2 is evaluated before a public release candidate.
8. Extension scope: reliability and quality only; no downloader or bulk-capture expansion.
